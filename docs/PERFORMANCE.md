# Performance and accessibility verification

The build fails when initial statically imported JavaScript reaches 200 KiB gzip or any noninitial JavaScript chunk reaches 100 KiB gzip. The check traverses Vite's manifest imports; dynamic routes and the HTML scan worker remain separate. Hashed assets get one-year immutable caching, entry HTML/no service worker get no-cache, and authenticated API responses are not cached by a CDN or worker.

Query freshness: class/file lists 60 seconds; lessons/published versions 10 minutes; chat/notifications 0; admin stats 30 seconds. Retries back off; window-focus refetch is disabled for large lists. Mutations invalidate affected query keys. Membership, settings, shared metadata, chat, and notifications have Realtime invalidation. Search debounces 300 ms, paginated lists cap rendered rows, and uploaded HTML is fetched only when opened.

Lighthouse is deliberately **not** installed: the user requested unchanged dependencies. Before launch, use the browser's Lighthouse panel on the deployed dev dashboard with a representative member account, mobile throttling, and a clean browser profile. Target performance 90+, LCP <2.5 s, INP <200 ms, CLS <0.1. Record the tested URL/build/date/device and reports in a private operator location; do not publish member screenshots or data. A fixture-backed smoke result does not establish production performance.

Playwright runs axe against public pages and main member/admin routes in light/dark. Serious/critical violations fail CI. The smoke also checks mobile overflow and keyboard focus, persisted answers, and sign-out cleanup. Manual keyboard verification before launch: login/policy; class/lesson creation; vault folder navigation, filters, upload and signed download; every question type and timer; chat compose; review/admin controls. Verify focus visibility, logical order, errors/live feedback, 200% zoom, reduced motion, light/dark contrast, and narrow layouts. WCAG 2.2 AA is the target; formal compliance is not certified.
